项目定位

AppCenter 把「企业软件商店」拆成两个可独立部署的部分：一份不含 UI 框架依赖的 领域引擎，和一个提供目录、审批、鉴权、审计与安装包分发的 目录服务端。引擎只通过接口与外界交互，因此同一份业务逻辑可以被 Web、Electron、Tauri 或原生壳复用。

终端管控类能力（行为采集、Web 中间人、锁屏、远程桌面、驱动级进程拦截、静默保活） 不在本项目设计范围内。软件安装始终以可见、可取消的方式进行。

能力矩阵

目录与检索

分类树、子分类聚合、中文搜索、贝叶斯评分、运营位、专属应用、捆绑包。

本机清单

HKLM 64/32 + HKCU 卸载项读取，三根并行扫描，落盘缓存 + 增量刷新。

安装执行

MSI / NSIS / Inno / MSIX / 归档 / 脚本的执行计划，静默与手动双模式。

下载与校验

Range 断点续传，sha256 + 体积双校验，校验不过不进安装态。

残留清理

只读扫描出清理计划，注册表类先导出 .reg 备份，可撤销，默认 dryRun。

审批与治理

安装前置审批闸门、通知回路、服务端角色鉴权与关键操作审计。

包结构

包职责

快速开始

需要 Node >= 24，用 --experimental-transform-types 直接运行 TypeScript，无构建步骤。

npm install

# 服务端：建库 + 灌演示数据
node --experimental-transform-types packages/server/src/main.ts --seed

# 客户端壳（另开一个终端）
node --experimental-transform-types packages/cli/src/main.ts search wps
node --experimental-transform-types packages/cli/src/main.ts demo

# 桌面应用窗口（独立窗口 + 任务栏图标，非浏览器标签页）
npm run desktop

# 校验
npm run typecheck
npm test

设计原则

  1. 引擎与 UI 分离。宿主只需实现 WindowHost （create/show/hide/close/focus）并订阅 onJob。
  2. 注册表读写分级。读取走只读接口；任何写入删除只出现在显式清理计划里， 且必须同时满足风险勾选、路径在白名单内、确认串正确，默认 dryRun。
  3. 下载即校验。版本必须带 sha256 + sizeBytes， 校验不过不进安装态。
  4. 审批是安装前置闸门。受控应用在拿到有效凭证前停在 awaiting_approval，不会先下载再拦。
  5. 装后校验与失败清理。安装退出后回读注册表确认真实版本； 成功、失败、异常都按开关清理安装包。
  6. 首屏不卡。清单落盘缓存命中即返回，过期走增量刷新，卸载根并行扫描。
  7. 自升级可回滚。暂存校验通过后写 pending 标记，启动时未 commit 即回滚。
